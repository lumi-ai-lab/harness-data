# 社群用户数指标分析报告模板

> 说明：本模板用于用户运营分析下的社群用户数指标专项分析报告。所有数值、同比、环比、区域排名、异常点、诊断事实和根因判断必须来自 CLI 输出。
> CLI 未返回的指标行、指标组或段落直接省略，不写缺失说明，不保留占位符，不使用本地 demo 数据或静态示例值。

## 通用填充规则

- 社群用户数是用户触达与渠道效率维度下的叶子指标，反映企业微信社群的私域触达能力。
- 父指标为可触达用户数（`reachMemberNum`），固定链路：`可触达用户数 -> 社群用户数`。
- 本报告核心问题是判断社群用户数当前规模及变化方向，区域结构分化是否合理，以及社群渠道渗透率是否在提升。
- 区域和趋势证据只用于解释社群用户数的结构分化和异常，不扩展为用户经营总览报告。
- 用户报表不支持品类过滤，不输出品类排名、品类拖累或品类贡献。
- 活跃用户数、新消费用户数、VIP 分层会员数、休眠/流失指标归入第三章，不得放入本报告。
- 会员复购率、消费会员数、复购会员数、复购会员消费频次、会员销售占比等归入第四章，不得放入本报告。
- 诊断必须基于已返回数据，使用"现象 -> 影响 -> 推断"的逻辑，不把通用业务常识写成已发生事实。
- 根因必须受 CLI 证据约束；CLI 只支持趋势或结构异常时，只能写"可能""倾向于"。
- 社群用户数 `threshold` 为 null，无预设阈值。
