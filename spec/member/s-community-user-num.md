# 社群用户数指标详情

> 数据来源：`qdm-cmr-cli indicator detail --code communityUserNum --full`

## 一、基本信息

| 属性 | 值 |
| :--- | :--- |
| 指标中文名 | 社群用户数 |
| 指标英文 code | `communityUserNum` |
| 业务定义 | 企业微信社群中的用户数量 |
| 统计逻辑 | 企业微信社群中的用户id去重计数 |
| 业务环节 | 用户触达与渠道效率 |

## 二、指标定位

- 社群用户数是可触达用户数的直接子指标，属于叶子节点（无下级子指标）。
- 所属维度：用户触达与渠道效率维度。
- 报告章节：第五章 用户触达与渠道效率维度深度拆解。禁止放入第三章（用户规模与分层结构）、第四章（会员价值与复购转化）。
- 所属指标组：渠道触达指标。
- 固定拆解链路：`可触达用户数 -> 社群用户数`。
- 归入用户触达与渠道效率链路中的私域触达指标，反映企业微信社群的用户覆盖能力。
- 用户报表不支持品类过滤，不输出品类排名、品类拖累或品类贡献。

### 3.2 趋势表现

> 数据来源：`qdm-cmr-cli report user trend --indicator communityUserNum`

近 30 天（2026/04/25 ~ 2026/05/24）社群用户数在 102.14 万 ~ 103.66 万区间波动：

- 趋势低点出现在 2026/05/04（102.14 万），随后逐步企稳回升。
- 趋势高点出现在 2026/05/24（103.66 万），为近 30 天峰值。
- 近 30 天内社群用户数保持 102 万以上水平，05/18 后连续 7 天持续回升，呈稳健增长趋势。
- 与去年同期相比，当前值均大幅高于同期比较值（去年同期约 68~70 万），反映社群渠道建设取得显著成效。

## 五、诊断规则

### 5.1 诊断逻辑

- 社群用户数诊断遵循"现象 -> 影响 -> 推断"三段式结构。
- 现象：来自 CLI 的社群用户数数值、同比环比、区域排名或趋势异常点。
- 影响：社群用户数变化对父指标（可触达用户数）的传导后果，以及对整体私域触达能力的评估。
- 推断：基于 CLI 已返回证据的有限根因判断。CLI 只支持趋势或结构异常时，只能写"可能""倾向于"。
- 根因未经 CLI 证据支持时，禁止断言为确定事实。

### 5.2 典型诊断场景

| 场景 | CLI 证据条件 | 诊断方向 |
| :--- | :--- | :--- |
| 社群用户数持续增长 | 当前 > 上月均值，mom > 0 连续多日 | 评估社群拉新策略有效性，关注社群用户活跃转化率 |
| 社群用户数出现下降 | mom < 0，趋势连续下滑 | 排查社群流失原因，判断是否为退群高峰或运营活动空窗期 |
| 区域分化扩大 | 区域间社群用户数差异加剧 | 判断低渗透区域是否具备社群运营启动条件，或是否存在资源投入不足 |
| 趋势中出现异常低点 | trend 中 single-day 显著低于 30 天均值 | 排查当日是否有批量退群或系统数据异常 |

### 5.3 区域诊断指引

- 区域社群用户数差异大时，诊断应关注各区域社群运营阶段差异（铺开期 vs 稳定期）。
- 同比增速异常高的区域（如运营直管 +14.44%）需关注是否基数过低导致的统计效应。
- 社群用户数变化不应直接等同于私域运营效果，需结合社群活跃度、转化率等指标综合判断。

## 六、边界与禁放规则

- 社群用户数是当前主指标，可触达用户数只能用于父级传导，不能替代主指标行。
- 官媒用户数、抖音用户数、会员数作为同组渠道触达指标，只能作为参照补充，不替代当前指标。
- 活跃用户数、新消费用户数、VIP 分层会员数、休眠/流失指标归入第三章，不得放入本章节。
- 会员复购率、消费会员数、复购会员数、复购会员消费频次、会员销售占比、交叉会员数、线上/线下消费会员数归入第四章，不得放入本章节。
- 品类维度指标一律不输出（用户报表不支持品类过滤）。
- 区域、趋势证据只能用于解释社群用户数结构分化和异常，不扩展为经营总览或跨维度分析。
- 本指标固定归入用户运营报告第五章（用户触达与渠道效率维度深度拆解），禁止放入第三章（用户规模与分层结构）和第四章（会员价值与复购转化）。
- 所有数值、同比、环比、排名、异常和根因必须来自 CLI 输出；CLI 未返回的指标行、指标组或段落直接省略，不写缺失说明，不保留占位符，不使用本地 demo 数据。
