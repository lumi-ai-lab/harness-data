# 官媒用户数指标详情

> 数据来源：`qdm-cmr-cli indicator detail --code officialMediaUserNum --full`

## 一、基本信息

| 属性 | 值 |
| :--- | :--- |
| 指标中文名 | 官媒用户数 |
| 指标英文 code | `officialMediaUserNum` |
| 业务定义 | 统计周期内，最后一天的微信公众号"不卖隔夜肉"的粉丝数量 |
| 统计逻辑 | 微信公众号"不卖隔夜肉"的粉丝数量 |
| 业务环节 | 用户触达与渠道效率 |

## 二、指标定位

- 官媒用户数是可触达用户数的直接子指标，属于叶子节点（无下级子指标）。
- 所属维度：用户触达与渠道效率维度。
- 报告章节：第五章 用户触达与渠道效率维度深度拆解。禁止放入第三章（用户规模与分层结构）、第四章（会员价值与复购转化）。
- 所属指标组：渠道触达指标。
- 固定拆解链路：`可触达用户数 -> 官媒用户数`。
- 归入用户触达与渠道效率链路中的官方媒体触达指标，反映微信公众号粉丝覆盖能力。
- 用户报表不支持品类过滤，不输出品类排名、品类拖累或品类贡献。
- **重要提示**：该指标仅在 CLI 返回有值时展示。当前 `indicators` 子命令未返回该指标值，但 `trend` 子命令可返回趋势数据。

## 五、诊断规则

### 5.1 诊断逻辑

- 官媒用户数诊断遵循"现象 -> 影响 -> 推断"三段式结构。
- 现象：来自 CLI 的官媒用户数数值、同比环比、趋势异常点（区域数据当前不可用）。
- 影响：官媒用户数变化对父指标（可触达用户数）的传导后果，以及对官方媒体触达能力的评估。
- 推断：基于 CLI 已返回证据的有限根因判断。CLI 只支持趋势异常时，只能写"可能""倾向于"。
- 根因未经 CLI 证据支持时，禁止断言为确定事实。

### 5.2 典型诊断场景

| 场景 | CLI 证据条件 | 诊断方向 |
| :--- | :--- | :--- |
| 官媒用户数持续增长 | 趋势逐日微弱净增长 | 评估公众号内容运营效果，判断涨粉是否来自爆款内容或活动推广 |
| 官媒用户数增长停滞 | 趋势连续多日持平或微降 | 排查公众号内容更新频率和质量，判断是否存在取关高峰 |
| 趋势中出现异常取关 | trend 中 single-day 显著下降 | 排查当日是否有负面舆情或违规内容推送 |
| 同比增速放缓 | yoy 逐月收窄 | 判断公众号涨粉天花板是否接近，是否需要拓展新内容平台 |

### 5.3 诊断限制

- 当前 `indicators` 子命令未返回该指标值，诊断需依赖 `trend` 子命令数据。
- 区域数据不可用，无法进行区域结构分化诊断。
- 官媒用户数变化不应直接等同于内容触达效果，需结合推文阅读量、互动率等指标综合判断。

## 六、边界与禁放规则

- 官媒用户数是当前主指标，可触达用户数只能用于父级传导，不能替代主指标行。
- 社群用户数、抖音用户数、会员数作为同组渠道触达指标，只能作为参照补充，不替代当前指标。
- 活跃用户数、新消费用户数、VIP 分层会员数、休眠/流失指标归入第三章，不得放入本章节。
- 会员复购率、消费会员数、复购会员数、复购会员消费频次、会员销售占比、交叉会员数、线上/线下消费会员数归入第四章，不得放入本章节。
- 品类维度指标一律不输出（用户报表不支持品类过滤）。
- 趋势证据只能用于解释官媒用户数变化和异常，不扩展为经营总览或跨维度分析。
- 本指标固定归入用户运营报告第五章（用户触达与渠道效率维度深度拆解），禁止放入第三章（用户规模与分层结构）和第四章（会员价值与复购转化）。
- 该指标仅在 CLI 返回有值时展示；`indicators` 子命令未返回值时，报告应省略此指标。
- 所有数值、同比、环比、异常和根因必须来自 CLI 输出；CLI 未返回的指标行、指标组或段落直接省略，不写缺失说明，不保留占位符，不使用本地 demo 数据。
